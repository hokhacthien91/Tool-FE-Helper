Banner Cloner

Clone a single source artboard (or a multi-frame step-animation set) into multiple banner sizes, then export the whole set as JPG/PSD/PNG assets and a structured JSON layer dump — all without leaving Photoshop. Built for production banner-ad workflows where one master design needs to ship across 10+ sizes (and optionally 2–10 animation frames).

Who is this for? Designers and motion artists in agency/studio teams producing display-ad banner sets (300x250, 728x90, 970x250, …) from a single master design. Pairs with the web-ui generator (banner-cloner-v1 JSON schema) to skip the hand-coded HTML step.

1. Quick Start

  1. Open your master PSD in Photoshop and select any layer inside the source artboard (the plugin walks up to the parent artboard automatically). Cmd/Ctrl-click in the Layers panel to select multiple sources at once (e.g. F1 + F2 + F3 frames).
  2. Open the panel: Plugins ▸ Banner Cloner.
  3. Type or pick target sizes (e.g. 300x250 728x90 970x250) — separated by spaces or commas. Variant prefixes are supported: v1-300x600, v2-300x600. Frame prefixes are also supported: F1-300x600, F2-300x600.
  4. Click Clone Artboards. Each new size appears as a fresh artboard in the same document, side-by-side with an 80px gap. Multi-source workflow stacks each frame's row beneath the previous one.
  5. (Optional) Click Export to save all artboards as JPG + PSD into a structured output folder, or Split to Documents to break each artboard into its own PSD file.
  6. (Optional) Switch to Assets tab to export individual layer/group assets per artboard.
  7. (Optional) Click Export Layer JSON in Settings to emit a banner-cloner-v1 schema dump consumable by the web-ui generator.

3. Core Features (in detail)

3.1 Clone Artboards (single & multi-source)

Duplicates the selected source artboard(s) into multiple new artboards in the same document. The original is preserved and never modified. Each clone is positioned to the right of the rightmost existing artboard with an 80px gap.

  • Same-doc cloning — fastest workflow; everything stays in one PSD until you decide to split.
  • Smart positioning — finds the rightmost edge of all existing artboards and lays new ones from there. Original artboard position is restored if it drifts during cloning.
  • Multi-source — Cmd/Ctrl-click to pick several source artboards at once. Each source clones a full row of targets; rows stack vertically with the original layout preserved.
  • Variant-aware — sizes prefixed v1-, v2-, … are kept distinct; rules apply per variant.
  • Frame-token match (Settings → Match source frame token) — when a source name carries a frame prefix (...-F2), only target sizes also prefixed with the same frame (F2-300x600) are cloned from that source. Sources without a frame token clone all targets (legacy behaviour). Toggleable.
  • Three layout modes, picked automatically per size:
    • Uniform scale — when Uniform scale is on. Bypasses smart match and JSON rules; just scales the canvas + content proportionally to fit.
    • JSON rules — when a layer rule exists for the target size (highest priority).
    • Smart match — when no rule but Smart Match is on. Auto scales/repositions/cover-fits content groups.
    • Canvas only — when all three are off; just resizes the canvas, leaves layers untouched.
  • Live progress — a progress bar shows current target and total.

Built-in preset sizes (one-click chips, click to add/remove from the input):

300x250 300x600 160x600 728x90 320x50 300x50 970x250 480x320 1080x1080 1080x1920 1920x1080 1080x1440 1080x1350

3.2 Uniform scale (preserve ratio)

Toggle in Settings. When enabled, every target size scales the source content uniformly (smaller of targetW / srcW and targetH / srcH), then re-aligns the result inside the new canvas. Bypasses both smart match and JSON rules. Useful for purely uniform decks where layout direction doesn't change. Persisted in localStorage.

3.3 Smart Match (auto-layout)

Toggle in Settings. When enabled and no JSON rule exists for a size, the plugin:

  • Captures the source artboard's content layout (groups + their bounds) before cloning.
  • For each target size, scales content groups proportionally to fit the new canvas.
  • Repositions groups to maintain visual balance (centered/anchored).
  • Treats the layer/group named in Background Layer (default GG-background) as cover-fill — scaled to fully cover the new canvas, never just repositioned.
  • Falls back to fitting individual content layers inside the canvas when no group structure is found.
  • Honors group fit-lock for groups whose name contains fit-lock — the entire group scales as one rather than per-child.
First-pass layouts only. Always review and polish manually before delivery.

3.4 Layer Rules (per-size)

Define explicit position, size, and style overrides per layer per target size. Rules can be:

  • Auto-synced from your target-sizes list — every size in the input field gets a row in Settings → Layer Rules.
  • Imported from JSON — supports two formats:
    • Rules format — moduleName + sizes[] + elements[].
    • Layer-full format (PSD-tree) — exported by Banner Cloner's own Export Layer JSON or by sister tooling. Auto-detected and converted on import.
  • Single-variant collapse — if your import has only v1-300x600 for a given dim, it's automatically renamed to 300x600. Multi-variant dims keep their vN- / Fn- prefix. Frame-token prefixes are preserved verbatim.
  • Exported as JSON via Export Layer JSON — captures the full layer tree with the new banner-cloner-v1 schema (see §6).
  • Re-applied to existing artboards via Apply Rules to Existing — re-runs rules without re-cloning. Match key is the size suffix in the artboard name (v2-300x600, F2-300x600, or plain 300x600).
  • Per-layer scale override — rules can carry a scale field to multiply the imported size by a per-rule factor (driven by computeRuleScale).
  • GG- prefix gate (optional) — when on, rules apply only to layers whose names start with GG- (e.g. GG-headline, GG-cta). Other layers are ignored.

3.5 Background cover scaling

The layer/group named in Background Layer (default GG-background) is treated specially:

  • In Smart Match mode → scaled as cover to fully fill the new canvas.
  • In JSON rules mode → scaled and positioned per its rule entry (with optional rule scale factor).
  • The matcher is case-insensitive and persisted to localStorage so your custom background name survives across sessions.

3.6 Export (all artboards)

Visible only when the active document has more than 1 artboard. Workflow:

  1. Click Export → pick a parent folder.
  2. Plugin creates: {parent}/{base}-output-working-file-{HHMM-DDMMYYYY}/
  3. Inside, two subfolders: output/ for JPGs, working-file/ for editable PSDs.
  4. Each artboard → 1 PSD (full quality, maximize compatibility on) + 1 JPG (default quality 8 → ~75 in 0–100 scale, white matte).
  5. JPG width is capped at 3000px; oversized banners are downscaled while preserving aspect ratio.
  6. All filenames are lowercased and sanitized.

3.7 Split to Documents

Each artboard becomes its own PSD document (one window per banner size). Useful when you need to hand off individual files for review or upload. After splitting, the Documents tab appears and lets you batch-export everything in one click.

3.8 Export Layer JSON (banner-cloner-v1 schema)

Saves a complete, lossless JSON representation of every selected artboard's layer tree. The plugin auto-detects export mode (single / multi-frame / layer-full) from the document state and labels the JSON accordingly — but you can override via Override auto-detection in Settings.

Top-level shape:

{
  "schema": "banner-cloner-v1",
  "mode": "single" | "multi-frame" | "layer-full",
  "framePrefix": "F",            // when mode = multi-frame, e.g. "F"/"Step"
  "exportedAt": "ISO timestamp",
  "artboards": [
    {
      "artboard": "campaign-1200x628-F1",
      "frame": "F1",             // present when mode = multi-frame
      "width": 1200,
      "height": 628,
      "layers": [ ... ]
    }
  ]
}

Captured fields per layer:

  • Geometry — bounds (top/left/width/height) relative to the artboard, with parent-group offsets accounted for.
  • Text — font family, weight, size, color, line-height, tracking, alignment, text content.
  • Fills — solid color (RGB), gradient (with stops + angle, CSS-direction-friendly).
  • Effects — drop shadow, inner shadow, outer/inner glow, stroke, gradient overlay (frameFX).
  • Border radius — corner radii on shape layers.
  • Transform — rotation, flip, scale.
  • Masks — vector masks + raster mask gradient analysis (gradient direction, stop colors/opacities).
  • Smart Objects — original src filename, vector vs raster detection, original embedded size.
  • clipTo — sibling layer name a layer is clipped to (clipping mask base).
  • Asset filename binding — if you ran Export Assets first, the JSON's src field points to the actual exported PNG/JPG instead of the raw PSD reference.

Auto-rename duplicate layers (Settings, on by default) — before serializing, the plugin renames duplicate layer names within each artboard so paths stay unique. Required for downstream tools that key on layer names.

3.9 Export Assets (per-artboard)

Exports individual layer/group assets across selected artboards. Workflow:

  1. Open the Artboard picker at the top of the Assets tab — search, click All/None, or pick individual artboards. Selection persists per-document via localStorage.
  2. Click Get Images to scan picked artboards. Each detected asset appears as a row.
  3. (Optional) Click + Add Group to add a group manually as one flattened asset (useful when scan missed it).
  4. Per-asset controls (cycle by clicking):
    • Size mode: A / B / C / D — see §5 below.
    • Scale: 1× / 2× / 3× (default 2× outside Advanced mode, 1× inside).
    • Format: PNG / JPG (PNG default; JPG uses Advanced JPG quality, default 75).
    • Rename: edit the output filename inline.
    • Show in PS: button selects that layer in Photoshop's Layers panel.
    • Single export: per-row export skips the bulk flow and writes only that asset.
  5. Search & collapse — filter the asset list by name, or collapse all rows for a denser view.
  6. Duplicate detection — two assets that would write the same final filename are flagged in orange so you can rename one before export.
  7. Hidden layers are skipped automatically.
  8. Ignore list — comma-separated keywords (Settings); layer/group names containing any keyword are skipped during scan.
  9. Click Export Assets to write everything.

Output structure:

  • Default mode → {picked-folder}/assets-{docname}-{timestamp}/ with one subfolder per artboard.
  • Advanced mode (Custom output path) → {path}/{size}/assets/ per artboard. The root path must already exist (no auto-create) and must be absolute.

Advanced options (Assets tab → tick Advanced options):

  • Custom output path (required when Advanced is on) — must be absolute, must already exist. Validated on submit; field flashes red on error.
  • JPG quality (required, 0–100) — Default 75. Validated on submit. Maps to internal Photoshop quality 0–12.
  • "gg-" filter — only export layers/groups whose names start with gg- (case-insensitive). Strips the prefix from the output filename so files come out as logo.png not gg-logo.png.
  • Generate info-image.html — builds a gallery HTML at the export root after asset export. Quick preview of what was exported, grouped by size.

All Advanced settings are persisted to localStorage so they survive panel reloads.

3.10 Apply Rules to Existing

After importing JSON, click Apply Rules to Existing in Settings to re-run the layout pipeline on every artboard already in the document. Useful when you've tweaked the JSON and want to update without re-cloning. Only artboards whose name contains a recognized size suffix (300x250 / v2-300x250 / F2-300x250) are touched.

3.11 Refresh Source

Clicking Refresh Source (Settings tab info card) re-detects the active artboard(s) from the current selection. Use this whenever you change selection in Photoshop mid-session — including when you Cmd/Ctrl-click multiple artboards.

3.12 Logs panel

The bottom panel logs every action with timestamps. Behaviour:

  • Errors get a red highlight + 3-second flash on the header to grab attention.
  • "Complete" / "created" lines get a green highlight.
  • Errors auto-expand the panel if it was collapsed.
  • Copy button copies the entire log to clipboard for sharing.
  • Clear resets to Ready.
  • Click the Logs title to collapse/expand.
  • [PERF] entries appear when DEBUG_PERF is on — round-trip timings for tuning.

4. Export-mode Auto-detection

When you click Export Layer JSON, the plugin classifies the document into one of three modes — feeding the right hint into banner-cloner-v1.mode. Detection is automatic; override via Settings → Override auto-detection.

ModeDetected whenUsed by web-ui
single 1 artboard total in the selection. Base size for smart-pin reflow into all extra sizes.
multi-frame N artboards, all the same WxH. Frame tokens (e.g. F1/F2/F3 or Step1/Step2) are extracted from the trailing alphabetic-prefix segment in each artboard name. framePrefix is set when all frames share the same prefix. Each frame is reflowed independently → output = frames × extra-sizes.
layer-full N artboards at different sizes (already a full size set). Fed straight through — generator renders as-is, no reflow.

The detection result is shown live under Settings → Export mode as soon as artboards exist. The override dropdown lets you pick a mode by hand if the auto-detection is wrong (rare).

5. Asset Export Modes (A / B / C / D)

Each asset row in the Assets tab has a size mode toggle. Cycle through them by clicking the mode button.

ModeWhat it doesBest for
A — Layer bounds Exports the layer at its full layer bounds. Output canvas = layer size. Logos, icons, free-floating shapes that should keep their full extent.
B — Clip to artboard Exports only the visible intersection of the layer with the artboard. Output canvas = visible overlap area. Background images that overflow the artboard — you only want what's actually visible. Forced when Custom output path is set (the per-size folder structure assumes clipped backgrounds).
C — Trim transparent Like A, but trims transparent edges off the result. Sprite-style assets where padding is just empty pixels.
D — Edit Contents Opens a Smart Object's source content and exports that. Skipped for vector SOs (logged as "skipped: vector smart object"). Raster Smart Objects where you want the original embedded resolution rather than the on-canvas size.

Scale options per asset: 1× / 2× / 3× (default 2× outside Advanced mode, 1× inside).

Format options: PNG (default) or JPG (uses the JPG quality from Advanced settings; default 75).

6. JSON Formats & Schema

6.1 New schema: banner-cloner-v1 (output)

Produced by Export Layer JSON in v1.2.0+. Self-describing — explicit mode, framePrefix (when applicable), and per-artboard frame token. Consumable directly by the web-ui generator.

{
  "schema": "banner-cloner-v1",
  "mode": "multi-frame",
  "framePrefix": "F",
  "exportedAt": "2026-05-04T10:00:00.000Z",
  "artboards": [
    { "artboard": "campaign-1200x628-F1", "frame": "F1", "width": 1200, "height": 628, "layers": [ ... ] },
    { "artboard": "campaign-1200x628-F2", "frame": "F2", "width": 1200, "height": 628, "layers": [ ... ] }
  ]
}

6.2 Rules format (canonical, for import)

Authored manually or generated by sister tooling. Shape:

  • moduleName — campaign / module label, shown in the Settings info card.
  • sizes[] — list of { name, width, height }. Drives the size keys used to look up rules.
  • elements[] — per-layer entries with per-size overrides for position, size, font size, color, scale, etc.

6.3 Layer-full format (PSD tree, for import)

Output of Export Layer JSON's layer-full mode (or sister tooling). Auto-detected on import via isLayerFullFormat() and converted to rules format. Used internally to:

  • Round-trip designs through external tools.
  • Reuse one master's full layer tree as the spec for all sizes.
  • Bind the rule's src to actual exported PNG filenames (after running Export Assets).

6.4 Filename / artboard-name conventions

  • Plain size — 300x250: single layout per dim.
  • Variant — v1-300x600, v2-300x600: multiple alternative layouts per dim.
  • Frame — F1-300x600, F2-300x600 (or Step1-…): step-animation frames per dim.
  • Compound — campaign-300x600-F2: prefix + dim + frame token. The plugin parses any of these via parseFrameToken() + the variant detection regex.

8. Tips & Conventions

  • Name your master background group GG-background so it auto-cover-scales without configuration.
  • Prefix layers you want governed by rules with GG- (e.g. GG-headline, GG-cta). Combined with Require GG- prefix, this gives you a clean opt-in convention.
  • Sizes are persisted to localStorage, so the input field repopulates on next launch. Toggle states (Uniform / Smart / GG-prefix / Frame-match) are persisted too.
  • Use the Import JSON feature to apply a campaign-wide rule template across all sizes in one shot. The auto-fill will update the Target Sizes input too.
  • If you need 2 layout variants of the same dim (e.g. 300x600 portrait + landscape), use v1-300x600 and v2-300x600. Single-variant dims auto-collapse to 300x600 on import.
  • For step-animation banners, name your source frames ...-F1, ...-F2, ...-F3. Cmd/Ctrl-click all of them as sources, target sizes prefixed F1- / F2- / F3-, and let Match source frame token route each frame to the right targets.
  • Refresh Source if you change selection mid-session — it re-detects the active artboard(s).
  • For Asset export with Custom output path, run Export Assets before Export Layer JSON so the JSON's src fields point at real PNG/JPG filenames instead of .ai/.psd raws.
  • The log panel auto-scrolls; use the Copy button at the top to grab the whole log for sharing in tickets.
  • If the cloned artboards drift in position, click Refresh Source and re-clone — the plugin re-anchors from the rightmost edge of the document.

9. Known Limitations

  • Smart-match auto-layout is best-effort; complex designs may still need manual cleanup.
  • Asset export Mode D (Edit Contents) only works for raster Smart Objects — vector SOs are skipped (and logged).
  • Custom output path requires the root folder to already exist — no auto-create. Validation flashes the field red if it doesn't.
  • JPG export caps width at 3000px (downscaled); PSDs are saved at full resolution.
  • Only Photoshop is supported (UXP). Min host version: 23.0.0 (manifest v5, apiVersion 2).
  • Photoshop's color descriptor stores green channel as grain in some contexts — readers must check both fields to avoid G=0 magenta artifacts (the plugin's readRGB handles this).
  • Frame-token match needs the source's name to literally contain -F1, -F2, etc. — case-insensitive but the alphabetic prefix must be consistent across frames.
  • Multi-source clone is single-document only; cloning across separate PSDs at once isn't supported.

10. Installation

  1. Install the Adobe UXP Developer Tool (free download from Adobe).
  2. In UXP DT, click Add Plugin and pick this folder's manifest.json.
  3. Click Load. The panel appears under Plugins ▸ Banner Cloner in Photoshop.
  4. The panel docks at the right; minimum size 320×520, preferred 360×760 (docked) / 420×820 (floating). Resizable up to 1200×2000.
  5. Plugin id: com.oai.bannercloner.v2. Required permissions: full filesystem, code generation from strings, clipboard read/write.
